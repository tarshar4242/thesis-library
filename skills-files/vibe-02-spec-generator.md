# VIBE-02｜訪談轉規格書

## 這個 Skill 做什麼

MIS 完成一對一痛點訪談後，輸入往往是：
- 調查表欄位截圖或複製貼上的文字
- 訪談當下手寫的草稿或語音轉文字
- 兩者混合的凌亂段落

這個 Skill 的任務是把這些原始素材，轉成一份**任何人拿到都看得懂、可以直接拿去開發的規格書**。

---

## 輸入格式（彈性接受以下任何一種）

**類型 A：調查表貼入**
直接把調查表欄位文字複製貼上即可，例如：
```
姓名：王小明
部門：生產部
工作項目：每小時記錄各站產量
頻率：每天都要做
麻煩程度：很麻煩
四象限：B 區
是否為重點問題：是
現在怎麼做：去各站手抄數字再輸入 Excel
最花時間：加總容易出錯
希望工具做什麼：輸入數字後自動算好
目前花費時間：30 分鐘
每天發生次數：每天 2 次
希望縮短至：5 分鐘
預計每週節省：50 分鐘
```

**類型 B：口語訪談筆記**
不需要整理，直接貼原始文字即可，例如：
```
他說他每天最煩的就是要去現場抄數字，抄完回來還要手動加總，
常常加錯。他希望可以直接輸入就自動算，這樣一天可以省很多時間。
他說他不懂電腦，只要簡單能用就好。
```

**類型 C：混合輸入**
調查表 + 補充說明混合貼入，Skill 會自行辨識並整合。

## 輸出格式

輸出一份結構清晰的規格書，包含以下七個區塊：

---

### 📋 AI 工具開發規格書

**規格書編號**：[依序編號，格式 SPEC-YYYYMMDD-姓名縮寫]
**訪談對象**：姓名、部門、職稱
**整理日期**：[今天日期]
**整理人**：MIS

---

#### 1. 使用者是誰
- 誰會用這個工具
- 技術背景（不懂電腦 / 基本操作 / 熟悉 Excel）
- 使用環境（辦公室電腦 / 現場平板 / 手機）

#### 2. 核心痛點
- 現在怎麼做（用白話描述現況流程）
- 哪裡最花時間、最容易出錯
- 這個問題多久發生一次

#### 3. 成功標準
- 什麼叫做「這個工具有用」（用具體可衡量的指標）
- 目前花費時間 → 目標縮短至
- 每週預計節省時間

#### 4. MVP 範圍（最小可用版本，必做）
- 列出 3 到 5 個核心功能，每項一句話說清楚
- 強調：這個版本要能讓使用者獨立操作，不需要 MIS 在旁邊

#### 5. 延後項目（暫不做，記錄備用）
- 使用者提到但目前不納入的功能
- 說明延後原因（複雜度、優先順序、待確認）

#### 6. 限制與注意事項
- 使用者技術限制（不會打字、只用手機等）
- 環境限制（沒有網路、只能用 Windows、語言需求）
- 特殊說明（需要雙語介面、需要保留原始紀錄等）

#### 7. 建議開發工具 / 平台
根據使用者背景與需求，給出初步建議，例如：
- Google Sheets 自動化（適合已有 Excel 習慣的使用者）
- Claude Project 對話工具（適合需要文字整理的場景）
- VBA 自動化（適合 Outlook / Office 相關流程）
- Python 腳本（適合批次處理、跨系統整合）
- 簡單網頁工具 / HTML artifact（適合現場操作介面）

## 輸出品質準則

撰寫規格書時請遵守以下原則：

**白話優先**
每個欄位都用國中生看得懂的語言寫，避免技術術語。如果必須用技術詞彙，後面加括號說明。

**具體不抽象**
❌ 「希望能更方便」
✅ 「輸入完數字後，系統自動計算加總，不需要手動用計算機」

**保留原話風味**
如果使用者說了有特色的話，可以在引號內保留原話，讓規格書有人味。例如：
「使用者說：『我不懂電腦，只要簡單能用就好』，因此介面設計要極度簡化。」

**誠實標記不確定**
如果訪談資料不足以填寫某個欄位，不要自己補假資料，改用：
`[待確認：需要再問使用者這件事]`

**四象限判讀輔助**
若輸入包含四象限分區資訊，在規格書頂部加一行優先度說明：
- A 區（高頻 + 低痛）：可優化但非急迫
- B 區（高頻 + 高痛）：**優先開發**
- C 區（低頻 + 低痛）：暫時擱置
- D 區（低頻 + 高痛）：評估是否值得投入

## 輸出後的下一步提示

規格書輸出完成後，在最後加上這段提示：

```
---
✅ 規格書完成！建議下一步：
1. 把這份規格書存入 Claude Project 知識庫，方便後續開發時隨時調用
2. 執行 VIBE-03（任務拆解）：把 MVP 範圍切成可驗收的小里程碑
3. 執行 VIBE-04（Prompt 產生器）：把規格書轉成開發用的第一版 Prompt
如需修改規格書任何欄位，直接告訴我哪裡不對，我會重新調整。
```

## 邊界情況處理

**輸入資料非常少**
如果輸入不足 3 個欄位，不要硬生出規格書，改為提問模式：
「我看到的資訊只有 [列出已有內容]，還需要知道以下幾件事才能寫規格書：[列出缺少的關鍵問題]」

**同一個人有多個工作項目**
分開輸出多份規格書，每份對應一個工作項目，並在頂部標注「[1/3] 第一項工作」。

**輸入是泰語或英語**
台泰雙語環境下，如果訪談資料包含泰語，規格書統一輸出繁體中文版本，並在限制欄位標注「此工具需支援泰語介面或說明」。
