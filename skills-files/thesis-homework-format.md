# Thesis & Homework Format Skill

## 🎯 用途

為 Tarshar 產出符合她慣用格式的學術 Word 檔（論文大綱、研究計畫說明、課堂作業等），讓 Mac / Windows 11 / iPad / iPhone 四個裝置輪流使用時視覺一致。

## 📋 觸發時機判斷

| 情境 | 是否觸發 |
|---|---|
| 「幫我整理論文大綱」 | ✅ 主動觸發 |
| 「照那份論文計劃說明」 | ✅ 主動觸發 |
| 「這份作業做成 Word」 | ✅ 被動觸發（預設套用） |
| 「用學術格式整理」 | ✅ 主動觸發 |
| 「做成 FB 貼文」 | ❌ 不觸發（走 fb-post-tarshar） |
| 「翻譯論文」 | ❌ 不觸發（走 paper-translator / left-and-right） |
| 「做成對照版」 | ❌ 不觸發（走 paper-bilingual-notes） |
| 「用活潑一點的格式」 | ❌ 不觸發（她指定了非學術風格） |

**預設規則**：Tarshar 丟任何學術／研究內容請 Claude 做成 Word，**除非她明說要其他樣式，否則一律套用此格式**。

## 📐 格式規範（完整規格）

### 一、頁面設定（A4）

| 項目 | 值 |
|---|---|
| 紙張 | A4（11906 × 16838 DXA） |
| 上邊界 | 1588 DXA（≈2.77 cm） |
| 下邊界 | 1588 DXA |
| 左邊界 | 1361 DXA（≈2.37 cm） |
| 右邊界 | 1361 DXA |
| 頁首 | 709 DXA |
| 頁尾 | 709 DXA |

### 二、字型策略（中英混排）

**核心原則**：中文走「微軟正黑體」、英文與數字自動走 Arial，使用 docx-js 的 `font` 物件同時設定 `ascii` 與 `eastAsia`。

```javascript
const FONT = {
  ascii: "Arial",          // 英文、數字
  eastAsia: "微軟正黑體",   // 中文
  hAnsi: "Arial",
  cs: "Arial"
};
```

**裝置相容性說明**：
- Mac 有裝 Office 的使用者會有「微軟正黑體」；沒裝的 fallback 到「黑體-繁」，版面不會跑掉
- Windows 11 原生就有
- iPad / iPhone Word App：中文 fallback 到系統黑體，行高與字寬一致

### 三、字級、粗體、顏色規範

| 元素 | 字級（pt） | sz 值 | 粗體 | 顏色 | 對齊 | 裝飾 |
|---|---|---|---|---|---|---|
| 封面主標題 | 18pt | 36 | ✅ | 黑 | 置中 | — |
| 封面資訊列 | 12pt | 24 | ✅ | 黑 | 置中 | — |
| 目錄頁標題 | 14pt | 28 | ✅ | 黑 | 置中 | — |
| 目錄項目 | 12pt | 24 | 無 | 黑 | 靠左 | 行距 2 倍 |
| 章節標題（一、二、三） | **14pt** | 28 | ✅ | 黑 | 靠左 | **下方深藍單線 `1F4E79`**、段前 12pt、段後 24pt |
| 內文強調句 | 12pt | 24 | ✅ | 黑 | 靠左 | — |
| 一般正文 | 12pt | 24 | 無 | 黑 | 靠左 | 行距 1.5 |
| 項目符號 | 12pt | 24 | 無 | 黑 | 靠左縮排 | • 實心圓點 |
| 表頭 | 12pt | 24 | ✅ | 黑 | 置中 | 底色 `FFF3CD` 淺黃 |
| 表格內文 | 12pt | 24 | 無 | 黑 | 首欄置中、其餘靠左 | — |

### 四、行距規則

| 區塊 | 行距 | docx-js 寫法 |
|---|---|---|
| 封面 | 單行 | 不設 |
| 目錄 | **2 倍** | `spacing: { line: 480, lineRule: "auto" }` |
| 正文 | **1.5 倍** | `spacing: { line: 360, lineRule: "auto" }` |
| 表格內 | 單行 | 不設 |

（`line` 值 = 行距倍數 × 240，例如 1.5 × 240 = 360）

### 五、段落間距

| 區塊 | 段前 | 段後 |
|---|---|---|
| 章節標題 | 240 DXA（12pt） | 480 DXA（24pt）— 與內文有清楚層級差 |
| 正文段落 | 120 DXA | 120 DXA |
| 項目符號 | 60 DXA | 60 DXA |

### 六、分頁規則

- **封面**：獨立一頁，結尾加 PageBreak
- **目錄**：獨立一頁，結尾加 PageBreak
- **每個一級章節**（一、二、三、⋯）：**從新的一頁開始**
    - 作法：每個章節標題的段落設 `pageBreakBefore: true`
    - 第一個章節可省略（因為前面已有目錄的 PageBreak）

### 七、目錄頁設計

**使用靜態目錄（非 Word 自動 TOC 欄位）**：

- 目錄標題：「目錄」，14pt 粗體置中
- 目錄項目：章節名稱 + 引導點（dot leader）+ 右對齊頁碼
- **頁碼統一填 `0`**：Tarshar 產檔後自己填實際頁碼（她的使用習慣）
- 行距 2 倍，視覺寬鬆
- 跨裝置穩定（Mac/Win/iPad/iPhone 都正常顯示）
- 不依賴 Word 的欄位更新機制

### 八、章節標題下藍線

章節標題段落加 `border: { bottom: { color: "1F4E79", size: 6, style: "single", space: 1 } }`。

### 九、表格預設樣式

| 項目 | 值 |
|---|---|
| 表格總寬 | 9300 DXA（貼近文字區寬） |
| 外框 | 黑色 0.5pt 單線 |
| 內框 | 淺灰 `CCCCCC` 細線 |
| 表頭底色 | 淺黃 `FFF3CD` |
| 替代強調色 | 淺綠 `D6F0E0`（選用） |
| 儲存格內距 | 上下 80、左右 120 DXA |

### 十一、頁碼規則

| 項目 | 值 |
|---|---|
| 位置 | 頁尾置中 |
| 字型 | Arial |
| 字級 | 10pt（sz=20） |
| 起始頁 | 封面為第 1 頁，目錄為第 2 頁，第一章為第 3 頁依此類推 |
| 格式 | 阿拉伯數字（1、2、3⋯⋯） |

### 十二、檔名規則

格式：`[學號][姓名]_[課程]_[主題]_[YYYYMMDD].docx`

範例：`714630117羅靜娟_系統分析與設計_論文大綱_20260425.docx`

**固定資訊**（Tarshar 的）：
- 學號：`714630117`
- 姓名：`羅靜娟`

**每次產檔前 Claude 必問兩個欄位**（用自然語言問，不要逐條列）：

- 課程（例：系統分析與設計、知識管理專題）
- 主題（例：論文大綱、第三章文獻回顧）

日期取今天（YYYYMMDD）。

## 🛠️ 執行流程

### 步驟 1：確認檔名資訊
先問 Tarshar「這份是哪堂課、主題叫什麼」，她回覆後組合檔名。

### 步驟 2：檢查內容結構
把她提供的內容拆成：
- 封面資訊（若她沒給，問她主標題）
- 章節清單（用於產生目錄與分頁）
- 各章節內文（判斷是否含表格、清單）

### 步驟 3：執行產檔腳本
呼叫 `scripts/generate.js`，傳入 JSON 結構：

```javascript
{
  "filename": "714630117羅靜娟_課程_主題_20260425.docx",
  "cover": {
    "title": "碩士論文研究計畫說明",
    "subtitle": "副標（選用）",
    "info": "學生：羅靜娟 ｜ 學號：714630117 ｜ 2026/04/25"
  },
  "chapters": [
    {
      "heading": "一、研究主題",
      "blocks": [
        { "type": "para", "text": "..." },
        { "type": "emphasis", "text": "..." },
        { "type": "bullets", "items": ["...", "..."] },
        { "type": "table", "headers": ["步驟","動作","工具","產出"], "rows": [[...]] }
      ]
    }
  ]
}
```

### 步驟 4：驗證與輸出
1. 跑 `python /mnt/skills/public/docx/scripts/office/validate.py 輸出檔.docx`
2. 轉 PDF 預覽一眼（`soffice --convert-to pdf`）
3. 放到 `/mnt/user-data/outputs/`
4. 呼叫 `present_files` 給 Tarshar

## ⚠️ 注意事項

1. **不要自作主張加內容**：Tarshar 提供什麼就寫什麼，不要「幫她補」章節或段落
2. **章節編號固定用全形中文數字**：「一、」「二、」「三、」⋯⋯（符合她原檔慣用）
3. **表格寬度要等於內容區寬**：9300 DXA，且每欄寬度總和要相等
4. **遇到英文專有名詞**：不用手動換字型，`ascii="Arial"` 會自動處理
5. **iPhone 限制**：產檔後如果 Tarshar 說要在 iPhone 上看目錄，提醒她 Word App 對 TOC 支援較弱，建議她用 Mac/iPad 編輯，iPhone 當快速查看
6. **若她提供的內容沒有章節結構**（例如只是一段長文）：禮貌詢問她要不要我幫忙分章節，或是以單一章節形式呈現

## 🧪 可跨裝置驗證的測試

產檔後的視覺一致性檢查清單：
- [ ] Mac 打開：章節下藍線、目錄 2 倍行距、正文 1.5 倍行距都正確
- [ ] Windows 11：同上
- [ ] iPad Word App：字型 fallback 正常、分頁位置正確
- [ ] iPhone Word App：文字可讀（TOC 可能要點「更新」才會顯示）
