# VIBE-03｜任務拆解器

## 這個 Skill 做什麼

拿到 VIBE-02 規格書之後，最常見的下一個問題是：「那我要從哪裡開始？」

這個 Skill 的任務是：
1. 把 MVP 範圍拆成 3 到 5 個有順序的開發里程碑
2. 每個里程碑都有「做什麼、怎麼驗收、誰來驗」三件事說清楚
3. 給每個里程碑一個「給 AI 的任務指令」，讓你直接貼給 AI 開始開發
4. 標出最容易翻車的風險點，讓你提前防範

---

## 輸入格式

貼入 VIBE-02 輸出的規格書即可，或直接描述需求。
也接受口語描述：「我要幫品管員做一個自動統計不良品數量的工具，她現在是手動從紙本抄到 Excel，希望能自動計算不良率。」

### 🚦 開發順序邏輯

在里程碑清單後面，加一段說明為什麼這樣排順序：

```
里程碑這樣排的原因：
- 里程碑 1 是地基：[說明為什麼先做這個]
- 里程碑 2 是最小可用版本：[達到這裡，使用者就能開始試用]
- 里程碑 3 以後是加值：[說明後面幾個可以視情況跳過或延後]

建議的「可以停在這裡」節點：里程碑 [N]
理由：[此時使用者已經能獨立使用，後續為錦上添花]
```


## 里程碑設計原則

**每個里程碑要能獨立交付**
不能說「里程碑 2 要等里程碑 3 做完才能測試」，每個都要能單獨拿出來驗收。

**驗收條件要能用眼睛看到**
❌「系統正常運作」
❌「計算結果正確」
✅「輸入 3 筆不良品數量後，畫面顯示加總數字，與我用計算機算的結果一致」
✅「輸入空白欄位時，畫面顯示提示訊息，不會直接當機」

**給 AI 的任務指令要包含邊界**
每個指令都要說清楚「不要做什麼」，否則 AI 容易自作主張加功能：
「只做輸入和計算功能，不需要做儲存、不需要做帳號登入、不需要做手機版。」

**里程碑 2 就要讓使用者能試用**
最晚到里程碑 2，使用者本人就要能親手操作一次，不能等到全部做完才讓他看。
早點讓使用者試，早點發現他嘴上說要的和他心裡要的不一樣。

## 依照開發工具調整里程碑內容

根據規格書建議的開發工具，里程碑的內容會有所不同：

**Google Sheets / Excel**
- 里程碑 1：建立基本表格結構和欄位
- 里程碑 2：加入自動計算公式，完成核心功能
- 里程碑 3：美化介面、加入防呆提示
- 里程碑 4：使用者實際試用並回饋調整

**HTML / Claude Artifact 網頁工具**
- 里程碑 1：純輸入介面，沒有任何計算功能，只確認欄位正確
- 里程碑 2：加入計算邏輯，輸入後顯示結果
- 里程碑 3：加入錯誤處理（空白、非數字輸入）
- 里程碑 4：使用者試用，收集回饋調整

**VBA / Python 腳本**
- 里程碑 1：用假資料跑通基本流程，確認邏輯正確
- 里程碑 2：接入真實資料來源，完成一次端對端測試
- 里程碑 3：加入錯誤處理和使用者提示訊息
- 里程碑 4：使用者實際操作一次，確認獨立可用

**Claude Project 對話工具**
- 里程碑 1：確認 Project Instructions 的核心指令，用假資料測試輸出格式
- 里程碑 2：用真實資料跑一次完整流程，確認輸出符合需求
- 里程碑 3：給使用者實際操作，確認他能獨立觸發和使用

---

## 邊界情況處理

**規格書的 MVP 範圍只有 1 到 2 個功能**
不要硬拆成 5 個里程碑，2 到 3 個就夠：
「這個工具範圍很小，2 個里程碑就能完成，不需要硬切。」

**規格書有待確認欄位（[待確認：...]）**
在對應里程碑標注：
`⛔ 此里程碑依賴待確認資訊，建議先向使用者確認後再開始。`

**使用者技術能力很低（如：不懂電腦）**
里程碑中的「驗收負責人」改為「MIS 先驗收，確認後再帶使用者試用一次」，
並在給 AI 的指令中特別加上：「介面要極度簡化，只有一個按鈕，文字說明用國中生看得懂的語言。」

```
---
✅ 任務拆解完成！建議下一步：
1. 把「給 AI 的任務指令」存起來，從里程碑 1 開始逐一執行
2. 執行 VIBE-04（Prompt 產生器）：把規格書和里程碑 1 的指令合併成完整的開發 Prompt
3. 里程碑 2 完成後，執行 VIBE-05（驗收清單）：產出使用者版的驗收清單
提醒：每個里程碑做完先驗收，確認過了再往下走，不要一次把所有里程碑都丟給 AI。
```
