# 互動學習模板 Skill

## 核心理念

把任何「我想搞懂這個」的需求，轉化成一張**可以點、可以問、有狀態標記**的視覺地圖。

使用者不需要說出完整需求，只要在任何主題後面加上觸發詞，就立刻產出。

---

## 輸出規格

### 必備元素

**1. SVG 互動地圖（主體）**
- 使用 `visualize:show_widget` 工具產出
- 每個節點必須可點擊（`onclick="sendPrompt(...)"` ），點擊後自動在對話中深入該主題
- 節點顏色編碼：
  - `c-teal`：已完成 / 已掌握
  - `c-coral`：當前位置 / 進行中
  - `c-purple`：核心重點節點
  - `c-blue`：一般節點（待處理）
  - `c-gray`：起點 / 終點 / 輔助節點
- 每個節點右側或下方顯示 2 行說明文字（`class="ts"`）
- 若有「當前位置」，用 `c-coral` 標記並加上「← 你在這裡」標籤
- 右下角加圖例說明顏色意義

**2. 狀態標記（badge）**
- 已完成：`c-teal` 圓角矩形 +「✓ 完成」
- 當前：`c-coral` 圓角矩形 +「← 你在這裡」
- 待處理：`c-gray` 圓角矩形 + 「待開始」或留空

**3. 節點點擊行為**
- 每個節點的 `sendPrompt` 內容要具體、有脈絡，不是泛問
- 例：`sendPrompt('設計科學研究法DSR是什麼？適合AI輔助排班論文嗎？')`
- 而非：`sendPrompt('告訴我更多')`

## 執行流程

### Step 1：分析主題結構

收到「[主題] + 互動學習模板」後，先在腦中完成：

1. 這個主題有幾個階段 / 層次 / 面向？
2. 使用者目前在哪個位置？（若有上下文可判斷）
3. 哪些節點是核心重點（需要 `c-purple`）？
4. 流向是線性（流程圖）還是放射狀（概念圖）？

### Step 2：選擇佈局

| 主題類型 | 建議佈局 |
|---------|---------|
| 有先後順序的流程（論文步驟、學習路徑） | 垂直流程圖，左側節點 + 右側說明 |
| 並列概念（比較、架構層次） | 水平並排或矩陣 |
| 決策樹（有分支、條件判斷） | 樹狀，從上往下展開 |
| 概念地圖（知識關聯） | 中心放射狀 |

### Step 3：計算 SVG 尺寸

- 每個節點高度：單行 44px，雙行 56px
- 節點間距：20px
- 總高度 = (節點數 × 節點高度) + (節點數 × 間距) + 上下 padding 各 40px + 圖例區 80px
- viewBox 固定寬 680，高度依計算填入

### Step 4：產出前的自我檢查

- [ ] 所有節點是否都有 `onclick="sendPrompt(...)"`？
- [ ] `sendPrompt` 內容是否具體有脈絡？
- [ ] 顏色是否正確反映狀態（完成 / 當前 / 待處理）？
- [ ] 圖例是否完整？
- [ ] viewBox 高度是否足夠（最後一個元素 + 40px buffer）？
- [ ] 說明文字是否用 `class="ts"` 且顏色用 `fill="var(--color-text-secondary)"`？

## 輔助文字（地圖前後）

**地圖之前**（1-2 句話）：
說明這張圖呈現什麼、使用者現在在哪裡。

**地圖之後**（2-3 句話）：
指出最近的下一步是什麼，以及是否需要立刻行動。

不要寫超過 3 句，讓圖說話。

## 觸發詞對照

| 使用者說 | 觸發 |
|---------|------|
| `[主題] 互動學習模板` | 是 |
| `[主題] 學習地圖` | 是 |
| `[主題] 畫成互動圖` | 是 |
| `[主題] 視覺化` | 是（若上下文是學習情境） |
| `[主題] 互動式` | 是 |
| `[主題] 做成圖` | 是 |
| 只說「解釋一下 [主題]」 | 否，回到正常回應 |

---

## 品質標準

一張好的互動學習地圖，使用者看完後應該能說出：

1. 「我現在在哪」——位置感清晰
2. 「我下一步做什麼」——行動方向明確  
3. 「我想多了解這個，點一下就問到了」——探索路徑順暢

如果三個都達到，這張圖就是合格的。
