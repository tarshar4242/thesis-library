# Tarshar 陪跑教練視角 FB 打包技能

## 啟用條件

以下情境立刻觸發：

1. Tarshar 上傳簡報檔（.pptx / .pdf）並提到 FB、發文、貼文、拆頁
2. Tarshar 說：
   - 「丟一份簡報幫我做成 FB 貼文」
   - 「一份簡報 + 一段心情」
   - 「觀察者角度的貼文」
   - 「陪跑小隊」「陪跑教練」「四人小隊」
   - 「拆成 16:9」「橫式拆頁」
3. 即使只說「這份做成 FB」並附檔也觸發

---

## 角色設定（核心關鍵）

Tarshar 在這類貼文的身份是：

> **一名陪跑教練／輔導者**，手上有一支四人專案小隊。
> Tarshar **不在小隊裡**，是從旁陪跑、引導、觀察的人。
> 貼文要從「教練視角」出發，看這支小隊在專案裡走過了什麼。

這個身份帶來的寫作原則：

### 可以出現的主詞
- 「這支小隊」
- 「四人團隊」
- 「他們」
- （不出現「我們」，因為教練不在隊裡）

### 可以出現的動作
- 「我陪著走了幾週」
- 「看著他們把 106 萬筆資料⋯⋯」
- 「這次陪跑，觀察到⋯⋯」
- 「陪到最後，提煉出三個觀點」
- 「從旁邊看一份專案從零到交件」

### 要避免的
- ❌「我交了這份作業」（學生視角）
- ❌「我們一起做」（隊員視角）
- ❌「同學們看這裡」（非陪跑者）

---

## 調性切換（與 fb-post-tarshar 的差異）

本 skill 仍遵守 `fb-post-tarshar` 的核心風格 DNA（口語、不破折號、台灣繁中、tag 含 `#LearnAIwithTarshar`），但有三個關鍵調整：

| 面向 | fb-post-tarshar（原） | fb-deck-post（本 skill） |
|------|------|------|
| 視角 | 第一人稱學生 | 第三人稱教練觀察者 |
| 情緒濃度 | 高（修仙、閉關、收工 😭） | 低到中（保留口語，但去掉強烈自嘲）|
| 核心內容 | 自己的努力與領悟 | 對小隊的觀察與洞見 |
| 結構重點 | 過程 + 企圖心 | 觀察 + 觀點分析 |
| 收尾 | 自嘲情緒句（收工 😭） | 陪跑者的總結或提問 |

**允許輕微自嘲**（選擇性，視場合）：
結尾偶爾可有一句「陪到最後自己也跟著閉關」這類輕自嘲，但不能喧賓奪主。

## 雙產出工作流程

使用者上傳簡報 + 心情文字時，**同時產出兩件事**，不拆兩次對話。

### 產出物 A：FB 貼文

**結構骨架**：

```
[簡報/專案標題，用中括號框]
關鍵數字或架構（1-2 行）

陪跑脈絡（2-3 行）
例：「這支四人小隊做了 X 週」「我從旁邊看他們 Y」

觀察到的現象（2-4 行）
這是貼文主體，要有洞見
例：「最有趣的是，他們從第三週開始⋯⋯」

觀點／分析（2-4 行）
從觀察提煉出的結論或思考
AI 線索可埋在這裡（但用教練視角）
例：「這就是為什麼在 AI 時代，框架思考比工具更重要」

收尾（1-2 行）
陪跑者的總結、提問或期待
例：「下一棒實作，繼續看他們怎麼走」
```

**AI 的出現方式（教練版）**：

不是「我要做 AI」（學生視角），而是觀察 / 觀點中的「AI 時代」「AI 視角」：

- ✅「這支小隊在做的事，其實就是 AI 時代需要的底層能力」
- ✅「AI 可以幫你做很多，但問對問題還是人的工作」
- ✅「越往 AI 走，越發現框架思考比工具重要」
- ❌「他們要走 AI 的路」（這是學生視角延伸）
- ❌「我要做 AI」（完全錯）

---

### 產出物 B：16:9 拆頁圖

**技術規格**：
- 比例：16:9
- 尺寸：1920×1080（Full HD，FB 橫式最佳）
- 格式：JPG，品質 92%
- DPI：200（高畫質）
- 命名：`01_封面.jpg`、`02_[語意名].jpg`⋯⋯按頁序
- 交付：打包成 zip 檔

**技術流程**：

```bash
# Step 1: 若為 .pptx 先轉 PDF
python3 /mnt/skills/public/pptx/scripts/office/soffice.py \
  --headless --convert-to pdf 簡報.pptx

# Step 2: PDF 轉 JPG（200 DPI 對應 1920 寬）
pdftoppm -jpeg -r 150 -jpegopt quality=92 簡報.pdf slide
# 註：-r 150 對 10 吋寬的 16:9 簡報會產出約 1500 寬
# 若簡報是 LAYOUT_WIDE（13.33 吋）-r 150 會產出約 2000 寬
# 依實際簡報尺寸調整 DPI 讓寬度接近 1920

# Step 3: 確認尺寸後精修為 1920×1080
python3 resize_to_16_9.py  # 見下方範例腳本

# Step 4: 重新命名為語意檔名

# Step 5: 打包 zip
zip -r FB拆頁_16_9.zip images/
```

**resize 腳本範例**：

```python
from PIL import Image
import os

TARGET_W, TARGET_H = 1920, 1080  # 16:9

for src_file in input_files:
    img = Image.open(src_file)
    # 等比縮放到寬 1920，若高超過 1080 則以高為準
    img.thumbnail((TARGET_W, TARGET_H), Image.LANCZOS)
    # 若原圖已是 16:9，直接變成 1920×1080
    # 若比例略有差異，以白底補至 16:9
    canvas = Image.new("RGB", (TARGET_W, TARGET_H), "white")
    x = (TARGET_W - img.width) // 2
    y = (TARGET_H - img.height) // 2
    canvas.paste(img, (x, y))
    canvas.save(output_path, "JPEG", quality=92, optimize=True)
```

## 語意檔名對應邏輯

拆頁圖要有意義的檔名，讓 Tarshar 上傳時知道誰是誰。

**命名規則**：`{頁碼 2 位數}_{內容簡述}.jpg`

**產出方式**：
1. 讀每一頁的標題（簡報用 extract-text 讀，PDF 用 pdftotext 讀）
2. 提煉 2-8 字語意描述
3. 組合成檔名

**範例對照表**：

| 頁數 | 頁面內容 | 檔名 |
|------|------|------|
| 1 | 封面 | `01_封面.jpg` |
| 2 | 目錄/大綱 | `02_報告大綱.jpg` |
| 3 | 研究動機 | `03_研究動機.jpg` |
| 4 | 五大問題 | `04_五大問題.jpg` |
| 16 | 感謝頁 | `16_感謝頁.jpg` |

**無標題頁**的命名邏輯：
- 資料表格頁 → `N_XX資料表.jpg`
- 純圖表頁 → `N_XX圖表.jpg`
- 章節過場 → `N_章節_XX.jpg`

## 完整執行流程

當使用者觸發本 skill 時，按此順序執行：

### Step 1：讀檔與理解
- 讀使用者上傳的簡報檔
- 若為 .pptx，先 extract-text 看每頁內容
- 若為 .pdf，用 pdftotext 或逐頁看
- 讀使用者給的「心情 / 脈絡文字」

### Step 2：產出物 A — 貼文
1. 抓取簡報骨架：關鍵數字、模組架構、核心方法
2. 結合使用者心情：找出可觀察的現象
3. 依「陪跑教練觀察者」骨架產出貼文
4. **自我檢查清單**（見下節）
5. 在對話中直接貼出

### Step 3：產出物 B — 拆頁 zip
1. 轉 PDF（若需要）
2. 轉 JPG，解析度對齊 1920×1080 的 16:9
3. 依語意命名
4. 打包 zip
5. 用 present_files 交付

### Step 4：同時呈現兩者
一個回覆裡同時包含：
- 貼文完整內容（可複製）
- zip 下載連結（圖片）
- 簡短說明：上傳順序、搭配建議

## 與 fb-post-tarshar 的協作關係

本 skill 是 `fb-post-tarshar` 的**延伸應用版**：

- 當 Tarshar 想以**學生第一人稱**分享心得時 → 用 `fb-post-tarshar`
- 當 Tarshar 想以**陪跑教練觀察者**分享，且有簡報要拆頁時 → 用 `fb-deck-post`

兩者不衝突、不重複。觸發條件是否提到「陪跑」「小隊」「觀察」「丟一份簡報」是判斷依據。

如果兩個都可能適用，優先問使用者「這次你是學生視角還是陪跑教練視角？」再決定。
