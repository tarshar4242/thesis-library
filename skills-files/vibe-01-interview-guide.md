# VIBE-01｜訪談引導產生器

## 這個 Skill 做什麼

MIS 拿到痛點調查表後，在進行一對一訪談前，把調查表欄位貼進來。
Skill 會幫你：

1. 判讀這個人值不值得深談（優先度評估）
2. 產出這場訪談專屬的問題清單（按優先順序排列）
3. 給每個問題附上追問引導，讓你不會冷場
4. 提醒你這個人可能有的盲點或需要特別確認的細節

---

## 輸入格式

直接把調查表欄位貼入即可，支援一次貼入一個人的所有工作項目。
格式不需要整理，凌亂也沒關係，Skill 會自行辨識。

**範例輸入：**
```
姓名：李美玲
部門：品管部
職稱：品管員
工作項目 1：統計不良品數量｜每天｜很麻煩｜B 區｜是重點問題
現在做法：手動從紙本轉入 Excel，數字多容易漏抄
希望工具：自動統計並產出不良率
目前花費：45 分鐘｜每天 1 次｜希望縮到 10 分鐘｜預計省 35 分鐘/週

工作項目 2：回報主管日報｜每天｜有點麻煩｜A 區
工作項目 3：計算各班達成率｜每週幾次｜很麻煩｜B 區
```

---

## 輸出格式

輸出分為三個區塊：

---

### 🔍 訪談前情報摘要

在你進門前，先給你這個人的快速側寫：

```
訪談對象：[姓名]，[部門]，[職稱]
訪談建議時長：約 [N] 分鐘
開發優先度：[🔴 高 / 🟡 中 / ⚪ 低]

優先度判讀邏輯：
- B 區工作項目有 [N] 個，其中 [N] 個標記為重點問題
- 每週潛在節省時間合計：約 [N] 分鐘
- 整體開發複雜度預判：[低 / 中 / 高]（依據希望工具描述判斷）

建議開場策略：
[根據這個人的職稱和工作內容，給一句讓對話熱身的建議，
例如：「他是品管員，可以先問他最近品質異常多不多，拉近距離再進入痛點。」]
```

---

### 📋 訪談問題清單

依照優先度排列，B 區重點問題排最前面。
每個工作項目給 2 到 3 個主問題，每個主問題附 1 到 2 個追問。

格式如下：

```
【工作項目 N】[工作內容描述]
優先度：[🔴 B 區重點 / 🟡 A/B 區 / ⚪ C/D 區]
建議花費時間：約 [N] 分鐘

主問題 1：[用白話問，讓受訪者自然說出來]
  → 追問：[如果他說「還好」或給很短的答案，你可以這樣追：...]
  → 追問：[如果他說「很麻煩」，進一步問：...]

主問題 2：[聚焦在「現在怎麼做」的細節]
  → 追問：[...]

主問題 3：[聚焦在「希望工具做什麼」的邊界確認]
  → 追問：[...]

⚠️ 這個項目需要特別確認：[調查表資訊不足或有模糊之處，提醒 MIS 要主動問清楚]
```

---

### 📌 訪談收尾清單

訪談快結束前，確認這幾件事都問到了：

```
□ 他提到的工具，他自己每天會用還是偶爾用？
□ 他的電腦環境如何？（有沒有網路、用什麼系統、會不會裝新軟體）
□ 除了他自己，還有沒有其他人也在做同樣的事？
□ 如果工具做出來，他願意花多少時間學？
□ 有沒有什麼「不能動」的東西？（不能改的格式、不能少的欄位）
□ 他有沒有提到其他同事也有類似困擾？（潛在擴展對象）
```

---

## 問題設計原則

**不要讓對方覺得在被審問**
問題要像聊天，不要像填表。
❌「你目前每次作業花幾分鐘？」
✅「你每次做完這件事，大概什麼時候才能做下一件事？」

**用「最」字挖痛點**
「這幾個工作項目裡面，哪個讓你最想直接消失？」
「你做這件事的時候，最常在哪個步驟想放棄？」

**用「如果」確認期待**
「如果有個工具幫你做這件事，你希望它長什麼樣子？是像 LINE 那樣傳訊息，還是像 Excel 那樣填表格？」

**用「以前有沒有」找現有解法線索**
「這個問題你以前有沒有試過什麼方法？哪個比較接近你要的？」

---

## 四象限快速判讀

輸出訪談問題清單前，先在內部判讀每個工作項目的優先度：

| 象限 | 頻率 | 痛感 | 建議策略 |
|------|------|------|----------|
| A 區 | 高頻 | 低痛 | 可優化，但排在 B 區之後 |
| B 區 | 高頻 | 高痛 | **優先深談，重點開發** |
| C 區 | 低頻 | 低痛 | 快速帶過，不深入 |
| D 區 | 低頻 | 高痛 | 評估投入產出比，謹慎承諾 |

B 區且標記「是重點問題」的項目，訪談時間分配最多，追問最深。
C 區項目可以只問一句「這個你覺得有需要改善嗎？」就帶過。

---

## 邊界情況處理

**調查表只有基本欄位、沒有「希望工具做什麼」**
在特別確認區標注：
`⚠️ 此項目未填寫期望工具，訪談時需要從零引導，建議用「如果」句型探索。`

**同一個人有超過 4 個工作項目**
先輸出前 3 個優先度最高的完整問題清單，第 4 個以後簡化為一句核心問題，並說明：
「項目較多，建議訪談時先聚焦前三項，若時間允許再帶到後面。」

**麻煩程度欄位是「還好」但四象限是 B 區**
這是潛在矛盾，在情報摘要標注：
`⚠️ 此受訪者自評麻煩程度低，但四象限落在 B 區，訪談時可以探索是否已習慣這個痛點而低估了它。`

## 輸出後的下一步提示

```
---
✅ 訪談準備完成！
建議把這份問題清單存在手機或印出來帶進去，不用每題都問，看對話走向彈性調整。
訪談結束後執行 VIBE-02（訪談轉規格書），把今天談到的內容轉成開發規格。
```
